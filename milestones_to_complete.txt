STRATEGY FOLLOW-UP (beyond the scoped milestone checklist)
- Connected diagnosis/repair history: implemented and validated.
  316 tests, lint, type check, build and 29 browser checks passed; no paid calls.
  Embedded Repair Lab retains original dataset and investigation IDs and appends
  candidate, assumption, measurement and comparison records. See docs/CONNECTED_REPAIR.md.
- Live GPT-6 Astra investigation and repair demonstration: not yet validated.
- Explicit structured Astra context across diagnosis and repair: implemented.
  322 tests, lint, type checking, production build and 29 browser checks passed
  (2026-09-16); existing Node module-type warning persists.
  Both repair provider turns receive validated diagnosis, evidence, hypotheses
  and verification history; no paid calls. This is not persistent hidden reasoning.
- Training-log ingestion into the autonomous loop: partially implemented.
  Optional bounded pasted logs become source-linked unverified observations.
  Richer artifact uploads, structured epoch diagnostics and log-only runs remain.
  327 tests, lint, type checking, build and 30 browser checks passed; no paid calls.
  See docs/TRAINING_LOGS.md.
- Broader falsification protocols beyond the accuracy-paradox test: implemented.
  Astra can declare a metric, unit, direction and threshold for any completed
  non-counterfactual diagnostic. The runtime evaluates exactly one matching
  measurement, fails closed on ambiguity, and final validation replays the
  result. A full distribution-shift path is covered by integration tests.
  See docs/GENERAL_FALSIFICATION.md.
- Domain objective to confirmed numeric repair policy: implemented.
  Astra produces a bounded review-only proposal from prose and dataset summaries;
  strict validation requires numeric error weights, a target, rationale and
  assumptions. Only explicit user confirmation copies it into authoritative
  Repair Lab fields. See docs/REPAIR_LAB.md.
- Active adversarial investigation: implemented as a bounded challenge pass.
  With retained datasets, Challenge WhyLab selects one unrun allowlisted
  diagnostic, executes the canonical deterministic engine, and appends its
  call/result/evidence/events to the same investigation without changing the
  diagnosis. It remains intentionally bounded and does not invent causal
  explanations or use a provider search loop. See docs/CHALLENGE_REVIEW.md.
- Richer artifacts and autonomous log analysis: implemented for the bounded
  investigator path. The UI accepts TXT/LOG/JSON/CSV artifacts; Astra receives
  source-linked observations plus structured local epoch history, heuristic
  findings and parser warnings in the same investigation context. Evaluation
  CSVs remain required and log claims remain unverified. See docs/TRAINING_LOGS.md.
- Optional investigator steering and specialist lenses: implemented.
  Requests can provide a bounded steering note and one prioritization lens;
  Astra must still follow the same allowlisted tools and evidence rules.
  Async fan-out, specialist sub-agent handoffs, and durable continuation need
  deployment-backed job/session infrastructure and remain deferred.
- Public deployment, paid-endpoint access/usage controls and hosted CI: remain.
- Deployment readiness probe and repeatable HTTPS smoke check: implemented.
  `/api/health` reports non-secret liveness/configuration booleans and
  `/api/health?ready=1` fails closed until access control, shared quota and AI
  configuration are present. `npm run check:deployment` validates a deployed
  origin without spending provider credits. Actual public deployment and a
  hosted GitHub Actions run still require external credentials.
